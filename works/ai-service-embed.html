Service Overview
채팅을 남기지 않고
이야기를 남깁니다
사용자가 캐릭터를 만들고, 상황을 골라 대화를 시작합니다. 대화 자체는 휘발되지만 기억·관계·분기는 방에 누적되고, 그 누적이 다음 대화의 품질이 됩니다.
CREATE
캐릭터를 만든다
성격·말투·비공개 설정을 적으면 하나의 인격이 됩니다. 배포 전 10턴을 시험해보고 설정을 고칩니다.
ENTER
상황을 고른다
같은 캐릭터라도 진입 지점이 다르면 다른 이야기가 됩니다. 세계관과 첫 대사가 한 쌍으로 묶입니다.
ACCUMULATE
방에 쌓인다
기억·관계·분기가 방 단위로 남습니다. 오래 한 방일수록 대화가 좋아집니다.
휘발되는 것과 남는 것을 먼저 갈랐습니다
메시지는 흘러가지만 기억 · 관계 · 분기 세 가지는 방에 남습니다. 남는 것을 먼저 정하고 나서야 무엇을 요약하고 무엇을 버릴지가 정해졌습니다.
MEMORY
기억
사실 단문으로 뽑혀 중요도를 갖습니다
AFFINITY
관계
0~100 점수와 5단계로 관리됩니다
BRANCH
분기
마음에 든 지점에서 방을 복제해 다른 결말을 보관합니다
셋 다 방(Room)에 붙습니다 — 사용자에게도 캐릭터에게도 붙지 않습니다. 이후의 결정 — 무엇을 요약할지, 넘칠 때 무엇부터 버릴지, 설정을 고쳤을 때 기존 방을 어떻게 할지 — 은 전부 “남는 것은 건드리지 않는다”는 한 줄에서 나왔습니다.

SM 05
문제 정의
Problem
캐릭터가 어제를 모르면
사용자는 매번 처음부터 설명합니다
초기 테스트에서 이탈이 몰린 지점은 응답 품질이 아니라 같은 설명을 두 번 하게 되는 순간이었습니다. 모델을 손대서 될 일이 아니었습니다 — 기억을 다루는 규칙이 없었습니다.
PROBLEM 01
어제를 모른다
컨텍스트 창을 넘기면 오래된 순서로 잘립니다. 사용자가 가장 중요하다고 여기는 약속이 가장 먼저 사라지는 일이 생깁니다.
→ 설계로 옮긴 답
중요도 순서로 자르기 — Memory에 importance 부여
PROBLEM 02
설정이 무너진다
턴이 길어질수록 캐릭터가 자기 말투를 잊습니다. 사용자는 이걸 “얘가 변했다”로 받아들입니다.
→ 설계로 옮긴 답
설정을 주기적으로 다시 주입하고, 반복 감지 시 생성 파라미터를 자동 조정
PROBLEM 03
품질과 비용이 반대로 간다
컨텍스트를 늘리면 좋아지지만 응답 한 건의 원가가 오릅니다. 무제한으로 좋게 하면 서비스가 남지 않습니다.
→ 설계로 옮긴 답
구간별 토큰 예산 상한을 먼저 정하고, 그 안에서만 품질을 다툼
“예측할 수 없다”가 아니라
“설명할 수 없다”가 문제였습니다
응답이 나쁠 때 사용자도 운영자도 이유를 모릅니다. 재현되지 않는 품질 문제는 고칠 수 없습니다.
그래서 먼저 만든 것
응답 로그
메시지마다 모델명·토큰·필터 결과를 남깁니다

Metric System

지표로 만들지 않았습니다
북극성은 DAU가 아니라 10턴 이상 지속된 주간 세션 수입니다. 턴 수만 보면 응답을 잘게 쪼개는 최적화가 나오므로 가드레일 지표를 함께 묶었습니다.
NORTH STAR
주간 몰입 대화 세션 수
10턴 이상 지속된 세션 / 주
DAU도 결제액도 아닙니다. 이 서비스가 잘 되고 있다는 것은 이야기가 이어졌다는 뜻이어야 했습니다.
왜 10턴인가
테스트에서 10턴을 넘긴 방은 다음 날 재방문율이 뚜렷하게 갈렸습니다. 그 아래는 캐릭터를 구경한 것이고, 그 위는 이야기를 시작한 것이었습니다.

턴 수를 북극성으로 잡으면 부작용이 하나 있습니다 — 응답을 짧게 잘라 턴을 늘리는 방향으로 최적화될 수 있습니다. 그래서 평균 응답 길이와 재생성률을 가드레일 지표로 함께 봅니다. 둘 중 하나가 나빠지면서 오른 턴 수는 성과로 세지 않습니다.

뺀 것
기억 시스템 — 이 서비스의 차별점을 Phase 1에서 뺐습니다
대신 지킨 것
요약·추출은 비동기 파이프라인과 별도 모델을 요구합니다. 8주 안에 넣으면 대화 자체가 불안정해집니다. 기억이 틀린 서비스보다 기억이 없는 서비스가 낫습니다.
뺀 것
원가상 최적인 짧은 컨텍스트 — 계산이 쉬운 안을 버렸습니다
대신 지킨 것
최소 6턴 보장과 기억 상한 100건. 왜 캐릭터가 어제를 잊었는지 설명할 수 있는 선에서 끊은 값입니다.

확인된 것과
아직 모르는 것
설계 판단 중 검증된 것과, 문서에 미결로 남겨둔 것을 나눠 적었습니다. 미결을 적지 않으면 정해진 척이 됩니다.
확인된 것
✓
기억을 열어 보인 것이 맞았다
틀린 기억을 고칠 수 있게 하자 불만이 줄었을 뿐 아니라, 사용자가 캐릭터의 응답을 스스로 납득하기 시작했습니다.
✓
실패 무과금이 신뢰를 만들었다
차단·폴백·타임아웃 미차감은 비용이 드는 결정이었지만 재화 시스템 전체에 대한 이의 제기를 거의 없앴습니다.
✓
안전 규칙을 구조로 못박은 판단
검증 결과 위치는 차이를 만들지 않았고, 규칙의 존재가 위기 대응을 67%에서 100%로 끌어올렸습니다. 다만 막는 순간 캐릭터가 깨지는 문제는 남았습니다.
✓
턴 수에 가드레일을 붙인 것
지표를 세우자마자 응답을 짧게 자르려는 압력이 실제로 생겼습니다. 가드레일이 없었으면 숫자만 올랐을 겁니다.
